# UI refresh plan — panel-by-panel

## Scope and invariants

Use the compact, task-led visual language established by `kicad-jlcpcb-interface`: slate surfaces, quiet metadata, a restrained blue accent, flat controls, compact table rows, semantic icons with visible labels, and one clear action hierarchy. The target already has most of the shared theme and component primitives; this refresh should improve layout and density rather than introduce a competing design system.

**Behavior is frozen for this pass.** Keep every existing button, option, selector, field, keyboard binding, callback, persistence rule, and KiCad IPC operation. Change only placement, grouping, spacing, sizing, nesting, and responsive presentation. Do not introduce new workflow steps or remove existing choices. Continue using the shared helpers in `theme.py`, `ui_components.py`, `_action_button`, `_add_tooltip`, and `_set_window_geometry`. No platform-specific window manipulation or custom file browsers.

## Global layout rules

1. Lead with the object and task. Keep supporting context adjacent to the control it explains; move detailed guidance into existing tooltips or documentation.
2. Use compact, consistent 4/8/12/16 px spacing. Remove stacked padding and repeated headings where one heading already identifies the group.
3. Size short dialogs to their content. For tables, show the number of real rows (with a small minimum and capped maximum), not a fixed empty viewport. Preserve scrollbars for overflow.
4. Keep action buttons in one predictable footer or one compact toolbar. The primary action is visually distinct; secondary actions are grouped by task, not scattered across repeated rows.
5. Avoid stretching short forms vertically. Only result lists, previews, and genuinely variable content should absorb spare space.
6. At constrained display sizes, content and primary actions must remain reachable; scroll content rather than clipping the footer.
7. Retain existing accessible text labels, semantic icons, tooltips, focus/keyboard bindings, light/dark palettes, and native Tk file dialogs.

## Panel plans

| Panel | Intended user flow | Layout changes | Controls and behavior retained |
|---|---|---|---|
| Functional Block Library | Search → select a block → inspect its facade or schematic → choose an action | Keep the proven two-pane browser. Make the search/results column visually compact; let the preview remain the dominant surface. Keep the selected name and short description directly above the preview. Present the block overview as concise, readable information beneath the preview without nested ornamental cards. Keep the bottom toolbar ordered by resource: refresh/libraries first, then block actions, then PCB actions, with Place aligned at the far right. Use a vertical sash to resize the preview against a compact overview. Provide Facade, Schematic, and linked PCB tabs with wheel zoom and drag pan. Reduce padding and avoid letting short result sets create unnecessary chrome. | Search, result columns, selected-block details, Facade/Schematic tabs, implementation and sheet selectors, overview data, Place, Implementation, Edit facade, Publish, Variants, Open PCB, PCB layouts, Refresh, Libraries, status and selection behavior. |
| Functional Block Placement Picker | Search → inspect → configure variant/profile → Place | Keep list and preview side-by-side. Tighten gaps around search, results, title, preview, and configuration selectors. Keep the variant/profile selectors together immediately before the preview/action region so configuration is read as one step. Size to content and available screen area. | Search/filter, result list, selected summary, facade preview, variant/profile selectors, Place/Cancel, arrow/Enter/Escape and double-click behavior. |
| Instance Configuration | Identify instance → select profile → adjust variant/parameters/layout → Save | Replace the tall, expanding stack with a compact form. Keep profile and variant first; lay parameter names and editors in aligned rows; keep PCB layout last. Do not let a short parameter list expand to fill the window. For unusually long parameter lists, allow content scrolling while keeping Save/Cancel visible. | Every profile including Custom, editable/read-only variant behavior, typed parameter widgets, PCB layout selector and variant-linked updates, Save, Cancel, validation, rollback and IPC undo behavior. |
| Facade Pin Layout Editor | Select pin → edit X/Y/angle/length → Apply | Fit the table height to the actual pin count (capped); keep the selected-pin geometry fields together directly below it. Put concise save/status feedback next to the action region. Remove empty table rows while retaining overflow scrolling. | Every pin row and column; X, Y, Angle, Length; immediate write/hash guard/library reload; Apply pin geometry and Close; keyboard selection and validation. |
| Manage Libraries | Review registered roots → Add/Create or manage selected root | Fit the table to the registered-root count. Keep Add library/Create library together as the collection actions. Keep Change folder/Unregister/Set default together as selected-root actions, with Close consistently at the far edge. Keep the default/environment role and folder path visible. | All columns, Add, Create, Change folder, Unregister, Set default, Close, native directory chooser, status, selection-state enabling and transactional rollback. |
| Implementations Manager | Review Default and alternatives → Add/Edit/Set default/Remove | Fit the table to the number of actual implementation rows. Place the concise default-resolution note immediately above it. Keep Add/Edit/Set default/Remove together in one action row; keep Close separate but aligned. | Default and named rows, file/role columns, Add, Edit default/Edit variant, Set default, Remove, autosave/retry, confirmation, profile/layout-link preservation and selection rules. |
| Implementation Details | Enter variant → choose starting point → provide source/copy → Use | Use a short content-first form. Keep Variant value at the top; put Starting point directly below when creation is allowed; show only the relevant source-file or copy selector row for the chosen mode. Keep Browse adjacent to the path field. Keep Use/Cancel in one footer. Recalculate window size after conditional controls change. | Variant value; all starting modes; file chooser; copy selector; blank schematic creation; Use/Cancel; validation, focus, Escape and cancellation behavior. |
| Add PCB Layout | Name layout → choose blank/existing source → associate implementation → Add | Compact vertical form with the name first, source mode second, conditional source path/chooser third, implementation association fourth, and action footer last. Collapse hidden source controls so blank-board mode does not reserve their space. | Name, both source modes, file chooser/path, implementation association (no unlink/no-link option), Add/Cancel, sidecar handling, file validation and failure rollback. |
| PCB Layout Manager | Review layouts → add/remove/default → assign selected layout to implementation → Close | Fit the table to the actual layout count. Keep Add/Remove/Set default grouped below the table; put the implementation selector and Assign action in a compact association row. Keep the no-unlink constraint as a short subdued hint. Align Close in the footer. | Layout/association/file columns; Add, Remove, Set default, implementation selector, Assign, Close; autosave/retry; default and last-layout invariants; multi-implementation links and open-created-board workflow. |
| Record Picker | Search → select a record → Select | Keep search directly above the result list, show only a compact selected-record summary where available, and keep Select/Cancel together. Fit the window to a short result set while preserving enough room for longer searches. | Search, filter, result rows, single-result fast path, Select/Cancel, Enter, arrow navigation, double-click and Escape. |
| Legacy Task Hub | Choose one of three compatibility categories → invoke an action | Keep the three tabs and two-column action grid, but reduce the introductory copy and gaps. Keep selection status visually subordinate and the Refresh/Close footer stable. Do not make this panel the primary route for create/place/publish. | All tabs, action buttons, icons, selection-aware enabled states, polling, Refresh selection and Close. |
| PCB / implementation choosers and small helper dialogs | Choose one existing implementation or layout | Use concise labels, compact selectors and one aligned action footer. Remove fixed large minimum dimensions where content is short. Keep the parent relationship and keyboard cancellation. | Existing options, default selection, Open/Use and Cancel, native file chooser and error handling. |
| Errors, confirmations and reports | Understand result → choose a safe next step | Keep messages short and specific to the affected object/path. Put diagnostic detail in logs, not permanent panel copy. Use one clear recovery/cancel action; retain confirmation where data loss or irreversible changes are possible. | All confirmation decisions, message content needed to explain consequences, cancellation semantics and rollback behavior. |
| Native file/directory choosers and KiCad-owned editors | Select a native path or open the appropriate KiCad editor | Keep OS/Tk-native file dialogs and existing KiCad launch flows. Do not create a custom tree browser or add desktop-specific ownership workarounds. | File filters, initial path/name, parent, cancel behavior, KiCad IPC operations and documented capability-gap messages. |

## Implementation and verification sequence

1. Apply the panel plans to the shared production Tk code, keeping behavior callbacks and control identifiers intact.
2. Add/adjust layout-contract tests for content-fit table heights, compact forms, conditional rows, and visible action footers. Retain all existing callback/IPC behavior tests.
3. Run the relevant UI contract tests, the full test suite, compile checks and Ruff.
4. Regenerate the production screenshots with `tests/capture_visual_docs.py`; inspect the browser, facade editor, library/implementation/layout managers, and small forms in light/dark themes. Check normal and constrained display sizes.
5. Run CI and inspect failures/logs/artifacts. State explicitly which layout properties are validated in the virtual display and which require a real KiCad desktop/Wayland check.

The refresh is complete only when all existing controls remain available, short panels no longer contain large empty table/form regions, the primary action stays visible, and the visual evidence is regenerated from production widgets.
