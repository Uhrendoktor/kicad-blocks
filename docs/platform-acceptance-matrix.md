# Cross-platform acceptance matrix

This page is the requirement-to-code-to-dependency-to-test traceability record for [issue #41](https://github.com/Uhrendoktor/kicad-blocks/issues/41). It describes the merged `main` state at `c9f5d7fbb8c37ad2f2a7a8f25a68c942fc06ff70`; it is not a platform-support declaration.

A requirement is **complete** only when the required user workflow has implementation, automated evidence, and the applicable real-platform evidence. A source-level portable API or a passing stubbed contract alone is not proof of end-to-end desktop compatibility.

## Status legend

| Status | Meaning |
| --- | --- |
| **Implemented / locally validated** | The behavior exists and its stated Linux/KiCad workflow is covered by tests. This does not imply every target OS is validated. |
| **Partial** | A supported subset works, but at least one explicit acceptance condition or target environment remains unverified. |
| **Blocked by upstream API** | The current KiCad Eeschema IPC surface lacks the native operation needed to complete the workflow without synthetic input. |
| **Not validated** | No trustworthy end-to-end evidence exists for the target environment or behavior. |

## Platform-by-feature evidence

| Target | Evidence currently available | Not established |
| --- | --- | --- |
| Ubuntu/Linux x86_64, Xvfb | Full CI integration path: CPython 3.12, KiCad CLI, Eeschema GUI/IPC, plugin discovery, PCB IPC, visual capture, and UI contracts. | Real desktop portal and taskbar/dock behavior; Xvfb is not a GNOME/KDE/Hyprland desktop validation. |
| Windows | Tk/file-dialog wrapper contracts execute in CI. | KiCad plugin installation/discovery, schematic/PCB IPC workflows, native chooser UI, and KiCad window ownership. |
| macOS | Tk/file-dialog wrapper contracts execute in CI. | KiCad plugin installation/discovery, schematic/PCB IPC workflows, native chooser UI, and dock/window ownership. |
| Linux ARM / other architectures | No full integration evidence is recorded. | IPC wheel availability and end-to-end product validation. |
| GNOME, KDE Plasma, Hyprland/wlroots | No real-session evidence is recorded in the latest CI run. | Native portals, focus/stacking, transient behavior, accessibility services, and compositor-specific regressions. |

The Linux-only IPC wheel is the accepted temporary packaging exception in issue #41. It is not evidence that the Windows/macOS runtime path works, and it is not permission to introduce OS-specific feature fallbacks into the shared plugin package.

## Remaining work, in dependency order

1. **KiCad upstream APIs:** land a schematic counterpart to `Board.interactive_move(items)` and a supported GUI Symbol Editor open/select operation; then implement and test the client integration without synthetic input.
2. **Platform packaging and discovery:** when the temporary exception is lifted, produce/publish supported `kicad-python` artifacts for the OS/architecture/Python combinations KiCad Blocks intends to support, then run live discovery and user workflows on Windows and macOS.
3. **Real desktop chooser/window validation:** run representative Windows, macOS, GNOME, KDE Plasma, and Hyprland/wlroots sessions; record KiCad, OS, Tk, and portal versions, screenshots, paths, and ownership behavior.
4. **Accessibility:** make the AT-SPI service available in the Linux GUI validation environment, capture a real accessibility tree for the editor and plugin windows, and assert meaningful accessible names/roles and keyboard paths. Keep a separate native accessibility review for Windows and macOS.
5. **Visual completion:** inspect refreshed light/dark screenshots at normal and constrained display sizes for every top-level window and verify all primary actions remain visible and operable.
6. **CI tiers:** keep fast portability contracts on every PR; schedule the broader product/OS-family integration and targeted compositor validation at merge/release cadence as defined in issue #41.

## Update protocol

When a requirement changes state, update the implementation/test/evidence links in the corresponding row. A row may move to complete only when the new evidence is linked and the platform boundary is explicit. Keep issue #41 open while any mandatory workflow or target remains partial, blocked, or unvalidated.
